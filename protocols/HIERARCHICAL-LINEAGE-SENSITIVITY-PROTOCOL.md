# P0y hierarchical-lineage sensitivity protocol

Status: frozen before inspecting the inferential sensitivity outputs generated by the accompanying script.

Date: 2026-09-16

## Question

Does the registered SoftMap minus soft-JS NDCG@5 result depend on the operational target-lineage taxonomy used for macro-averaging and inference?

This is a retrospective robustness analysis of the already frozen P0y experiment. It does not change the registered P0y decision. The model-level scores, target set, methods, panel, oracle, and contrast remain fixed; only the grouping used for aggregation or dependence-aware inference changes.

## Fixed contrast

For target checkpoint \(i\),

\[
d_i = \operatorname{NDCG@5}_{i,\mathrm{SoftMap}}
      - \operatorname{NDCG@5}_{i,\mathrm{soft\text{-}JS}}.
\]

For a grouping \(g\), checkpoint effects are averaged within group and groups are then weighted equally. Thus each level has an explicit estimand; coarse-level macro means are sensitivity estimands rather than replacements for the registered declared-lineage estimand.

## Frozen grouping levels

1. **Checkpoint**: one group per completed target. This is a deliberately fine anti-clustering bound.
2. **Declared release lineage**: the registered `family` field in the frozen manifest. This remains the primary estimand.
3. **Publisher namespace**: the lower-cased Hugging Face namespace before `/`. This is a reproducible owner-level coarsening, not a claim of biological or architectural ancestry.
4. **Implementation architecture**: the lower-cased frozen `model_type`. This is a deliberately severe dependence stress test. It denotes software architecture class, not canonical model ancestry.

No model-name parsing or outcome-dependent manual regrouping is allowed.

## Inference at each aggregation level

For the equal-group macro effect, report:

- number and size distribution of groups;
- mean paired effect;
- percentile 95% group-bootstrap interval (100,000 draws);
- two-sided paired sign-flip test (exact when there are at most 20 groups; otherwise 1,000,000 deterministic Monte Carlo draws);
- positive-group count and fraction;
- the registered-style robustness rule: interval lower bound above zero, raw two-sided \(p\le .05\), and at least 60% positive groups.

Holm-adjusted p-values across the four grouping-level sensitivity tests are reported descriptively.

## Estimand-preserving dependence stress tests

The registered declared-lineage point estimate is retained, but signs and bootstrap sampling are clustered at (a) publisher namespace and (b) implementation architecture. Cluster sign flips operate on sums of declared-lineage effects, preserving equal declared-lineage weighting.

### Pre-outcome structural amendment

The first schema-only execution stopped before writing an output because two declared lineages crossed `model_type` labels (`codeshell`: `codeshell` and `kclgpt`; `powerlm`: `granite` and `granitemoe`). Consequently, `model_type` is not a strictly nested parent of declared lineage. Before any valid sign-flip statistic was produced, the architecture dependence grouping was amended to the connected components of the frozen declared-lineage--`model_type` bipartite graph. This is the unique deterministic partition that keeps every declared lineage intact while placing lineages connected by an implementation class in the same dependence cluster. The descriptive target-level implementation-architecture macro remains unchanged. Publisher namespace is strictly nested and needs no amendment.

The stopped execution also exposed an implementation defect in exact sign construction: unsigned bit arithmetic represented \(-1\) as 255. The corrected implementation constructs signed values with `np.where`. The failed execution wrote no result artifact.

## Local taxonomy perturbations

Two adversarial checks are fixed:

1. **Leave-one-lineage-out**: enumerate all 43 omissions and report the full point-estimate range; run full inference for the omission producing the smallest mean effect.
2. **Single admissible merge**: enumerate every pair of declared lineages sharing a publisher namespace or implementation architecture. Reaggregate target effects after each single merge, report the full mean and sign-fraction ranges, and run full inference for the merge producing the smallest mean effect.

These perturbations test whether a single disputed split or influential lineage can reverse the conclusion.

## Interpretation rule

The registered result is called taxonomy-robust only if:

- the registered declared-lineage result is reproduced exactly;
- all four prespecified aggregation levels retain a positive mean and pass the registered-style rule;
- both estimand-preserving cluster tests reject at \(p\le .05\);
- the worst leave-one-out and worst admissible single-merge analyses retain a positive 95% interval lower bound and \(p\le .05\).

If a condition fails, the manuscript will report the specific resolution at which support is lost. Publisher and `model_type` analyses will never be described as verified ancestry.
